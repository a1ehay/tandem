# Tandem API (Java / Spring Boot)

Backend разрабатывается на Java 25 LTS и Spring Boot 4.1.2. Слои организованы как `http → service → repo`; Hibernate/Spring Data JPA используются для стандартных CRUD-сценариев, `JdbcTemplate` остаётся доступен для специализированных запросов. Backend независим от frontend build и Cloudflare Worker. Миграции PostgreSQL принадлежат отдельному проекту `database/` и запускаются через Flyway.

## Требования

- Java 25 (LTS)
- Maven 3.6.3 или новее
- Локальный PostgreSQL из корневого `compose.yaml`

## Локальный запуск

Из корня репозитория один раз создайте `.env` по образцу, задайте пароль и запустите PostgreSQL с Flyway-схемой:

```sh
cp .env.example .env
docker compose up -d postgres
docker compose --profile migrate run --rm migrate
```

Затем из `backend/` загрузите переменные из корневого `.env` и запустите приложение:

```sh
set -a
. ../.env
set +a
mvn spring-boot:run
```

Сервер слушает `0.0.0.0:8080` по умолчанию. Параметры приложения можно задать через `HTTP_HOST`, `HTTP_PORT`, `DB_URL`, `DB_USER`, `DB_PASSWORD` и `DB_POOL_SIZE`; секреты не хранятся в исходниках. Hibernate настроен на `ddl-auto: validate`: он проверяет соответствие entity-моделей уже созданной схеме и не создаёт/не меняет таблицы. Backend не запускает DDL/Flyway автоматически: сначала применяются миграции отдельным `database/`-проектом.

## Начальные маршруты

- `GET /healthz` → `{"status":"ok"}` — простой health-check, не проверяет доступность БД.
- `GET /actuator/health` — Spring Boot Actuator health; включает проверку DataSource.
- `GET /actuator/info` — информация о приложении.

Actuator наружу публикует только health и info, подробности health-ответа скрыты.

## Структура исходников и правила слоёв

- `src/main/java/com/tandem/api/http/` — контроллеры, входные/выходные HTTP DTO и обработка ошибок. Контроллеры вызывают сервисы, но не репозитории.
- `src/main/java/com/tandem/api/service/` — бизнес-сценарии, правила доступа и транзакционные границы; `service/port/` содержит независимые от Spring контракты доступа к данным.
- `src/main/java/com/tandem/api/repo/jpa/` — адаптеры портов, внутренние Spring Data интерфейсы, мапперы и JPA-сущности в `entity/`; `repo/jdbc/` — SQL для интервалов расписания и атомарной привязки досок.
- `src/main/java/com/tandem/api/domain/model/` — неизменяемые Java-модели, enum состояний и типизированные элементы JSON-документов без ORM/HTTP-зависимостей.
- Функциональные подпакеты добавляются вместе с реализацией конкретного сценария; заранее не создаём пустые CRUD-классы.
- `src/main/resources/application.yaml` — настройки с переопределением через окружение.
- `pom.xml` — зависимости и Maven-сборка.

Вызовы направлены от HTTP-слоя к сервисам и далее к persistence-адаптерам. На уровне зависимостей адаптеры реализуют интерфейсы из `service/port`; application-код не импортирует адаптеры, Spring Data, JPA или JDBC. Схема PostgreSQL изменяется только версионированными Flyway SQL-миграциями из `database/`.

## Repository Layer

Все девять портов автоматически получают реализации через Spring constructor injection. Бизнес-сервисы и новые HTTP-маршруты в этом этапе не реализуются.

| Порт | Назначение |
|---|---|
| `UserRepository` | Создание, поиск по ID/email с семантикой `citext`, пакетное чтение пользователей, изменение имени. |
| `StudentProfileRepository` | Создание и чтение профиля ученика, изменение класса. |
| `TutorSubscriptionRepository` | Создание начального состояния и чтение подписки. |
| `TutorStudentRepository` | Создание связи, чтение, список по репетитору/статусу, изменение данных и архивирование связи. |
| `LessonRepository` | Создание, поиск/список, расписание, условная смена статуса, запрос пересечений. |
| `TaskRepository` | Создание, поиск/список, содержание и условная смена статуса. |
| `BoardRepository` | Документы досок, лёгкие карточки, переименование, условная замена элементов, удаление непривязанной доски. |
| `LessonBoardRepository` | Идемпотентная привязка доски, чтение привязок одного/нескольких уроков и отвязка. |
| `PlannerRepository` | Создание, чтение и условная замена документа планера. |

Чтение отсутствующей записи возвращает `Optional.empty()`. Условная запись возвращает `Mutation.UPDATED`, `NOT_FOUND` или `CONFLICT`. Nullable поля моделей соответствуют nullable колонкам V1. `StorageException` различает уникальность, ссылочную целостность, CHECK/NOT NULL-ограничения, конфликт блокировки, недоступность БД и неожиданный сбой. Исходная причина сохраняется для диагностики, публичное сообщение не содержит SQL. Неверные параметры выборки возвращаются как `RepositoryArgumentException`/`InvalidCursorException`.

Списки возвращают неизменяемый `CursorPage`, `nextCursor` и `hasMore`. Лимит — 1–100, выборка использует `limit + 1`; cursor связан с полным набором фильтров и областью участника. Уроки упорядочены по `startsAt, id`; задачи — по `dueAt NULLS LAST, id`; доски — по `updatedAt DESC, id`; связи — по `createdAt, studentId`. Cursor не является credential или снимком БД: конкурентные изменения сортируемых полей могут переместить запись между страницами. Карточки досок не загружают JSONB. Пакетные методы пользователей/привязок принимают до 100 ID, чтобы сервис мог собрать страницу без N+1 запросов.

### Транзакции и конкурентные изменения

Каждая запись участвует в `REQUIRED`-транзакции; отдельный вызов атомарен, а несколько вызовов объединяются внешним `@Transactional` application use case. Изменение всегда выполняет flush до выхода из адаптера. Ошибки открытия/commit транзакции также переводятся в контракт хранения. После ошибки нельзя продолжать ту же транзакцию — она должна быть откачена.

Условные операции блокируют строку, обновляют managed-состояние из БД и проверяют ожидаемый статус или `updatedAt`. Для досок и планера передавать `updatedAt`, полученный при последнем чтении. Timestamp монотонно увеличивается с точностью PostgreSQL до микросекунды; stale-запись получает `CONFLICT`. Общего JPA `@Version` в V1 нет. Создание использует `persist`, чтобы дубликат первичного ключа не превратился в скрытый upsert; возвращаемая модель перечитывается с фактической точностью БД.

JPA и JDBC используют один DataSource и `JpaTransactionManager`. Перед JDBC-запросом persistence context сбрасывается через flush; после вставки привязки context очищается. ORM-сущности наружу не выдаются, поэтому сервис работает с независимыми Java-моделями.

### Ограничения V1

- Приглашения, credentials/OAuth identities, архивирование задач и платёжные изменения не реализованы: нужных таблиц/полей нет. Копирование задания — сервисный сценарий создания новой записи.
- Проверка роли репетитора/ученика, доступа, тарифа и допустимости бизнес-переходов остаётся в service/domain. ID в фильтре ограничивает выборку, но не заменяет авторизацию.
- Запрос пересечений расписания диагностический. Чтобы исключить гонку двух одновременных созданий урока, будущий сервис должен использовать общий механизм блокировки либо отдельную миграцию с exclusion constraint.
- HTTP ETag и новый API не реализованы; этот слой предоставляет timestamp-based условную замену документов для будущего сервиса.

## Интеграционные проверки

```sh
mvn verify
```

Проверки требуют работающий Docker и создают собственные PostgreSQL 17 Testcontainers. Они не используют локальную Compose-базу. Flyway в test scope применяет SQL из `../database/src/main/resources/db/migration`; путь передаёт Maven через `tandem.migrations.path`. SQL не копируется в backend, production backend не запускает Flyway. При недоступном Docker тесты завершаются ошибкой, а не пропускаются.

Проверяются mapping всех таблиц и JSONB-типов, ограничения, отсутствие записей, keyset-пагинация, пакетные проекции, конкурентные записи, устаревший JPA context, идемпотентные привязки, общий rollback JPA/JDBC и недоступность PostgreSQL. В проекте нет отдельно настроенного линтера; формат Java и `git diff --check` проверяются отдельно.

## Сборка

```sh
mvn -DskipTests package
```

Для этой версии проекта выбрана Java 25 LTS. Spring Boot 4.1.2 поддерживает Java 17–27, а Maven 3.6.3+; Java 25 является актуальной LTS-версией ([официальная документация Spring Boot](https://docs.spring.io/spring-boot/system-requirements.html), [дорожная карта Java](https://www.oracle.com/java/technologies/java-se-support-roadmap.html)).
