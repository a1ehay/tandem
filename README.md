# Tutdesk

Tutdesk — рабочее пространство репетитора и ученика: личные кабинеты, занятия, конференции LiveKit, интерактивная доска, задания, сообщения и планер.

В интерфейсе доступны три тарифа без подключённой оплаты: «Бесплатный» (только звонки), «Базовый» (399 ₽/месяц) и «Продвинутый» (1249 ₽/месяц). Старые значения `light` и `extreme` сохранены как внутренние совместимые идентификаторы базового и продвинутого планов. На бесплатном плане клиент LiveKit не разрешает включить вторую демонстрацию, если уже видит активную публикацию экрана в комнате.

Домашняя работа вынесена из планера в отдельный раздел. Для каждой работы сохраняются статус проверки и комментарий преподавателя; старые задания получают статус «Непроверено». Раздел Notion хранит отдельные страницы в существующей модели данных аккаунта. Поддерживаемые вложения открываются во встроенном сворачиваемом просмотрщике, остальные предлагаются для скачивания через защищённый API.

Во время звонка можно открывать другие разделы: комната остаётся подключённой в компактном окне, а пункт «Звонок» возвращает к ней. Кнопка «Пригласить участника» копирует ссылку именно на текущую комнату и не разрывает соединение организатора; вошедшие в Tutdesk пользователи могут открыть её на другом устройстве и присоединиться к тому же звонку. В разделе «Видеоуроки» ученик сохраняет ссылки YouTube и Rutube, преподаватель сохраняет их в свою библиотеку и назначает связанным ученикам. Карточку из лотка видеоуроков можно перетащить на доску. Встроенный плеер зависит от доступности видео и разрешения правообладателя на встраивание. На главной странице ежедневно показывается запись из `frontend/quotes_365_ru.json` по местной дате пользователя; адаптации помечаются отдельно.

## Запуск и сборка

Для просмотра статического интерфейса откройте PowerShell в папке проекта:

```powershell
py -m http.server 8000 --directory frontend
```

Откройте <http://localhost:8000>. Если команда `py` недоступна, запустите `python -m http.server 8000 --directory frontend`. Камера, микрофон и захват экрана доступны через localhost или защищённый HTTPS-сайт; браузер запросит разрешение после нажатия соответствующей кнопки.

## Структура проекта

- `frontend/src/client/` — клиентские ES-модули: состояние и локальное хранение, общие утилиты, шаблоны экранов, формы, геометрия доски и видеокомната.
- `frontend/` — исходники статического сайта и точка входа браузерного приложения.
- `cloudflare/worker.js` и `cloudflare/livekit-token.js` — маршрутизация Cloudflare Worker и выпуск временных токенов LiveKit.
- `backend/` — независимый Java/Spring Boot API на Java 25 LTS. Инструкции запуска — в [backend/README.md](backend/README.md), контракт — в [docs/backend/api.yaml](docs/backend/api.yaml).
- `services/realtime-service/` — подготовленная структура для будущего Go realtime-сервиса; разделение ответственности описано в [ARCHITECTURE.md](ARCHITECTURE.md).
- `database/` — отдельный Java/Maven-проект миграций PostgreSQL с Flyway; инструкции запуска — в [database/README.md](database/README.md), проект схемы — в [docs/database/database.md](docs/database/database.md).
- `compose.yaml` — единый Compose для PostgreSQL; переменные описаны в `.env.example`, а значения для каждого окружения задаются в локальном `.env` или в секретах production-сервера.

## Сборка сайта для публикации

Установите Node.js, если он ещё не установлен, затем из папки проекта выполните:

```powershell
node .\build.mjs
```

Результат появится в `dist/`. Каталог `dist/` не добавляется в Git.

## Аккаунты и база данных

Пользователи и данные кабинетов хранятся в Cloudflare D1. Пароли хешируются на Worker с PBKDF2-HMAC-SHA-256. После регистрации Tutdesk отправляет одноразовую ссылку подтверждения email; сессия хранится в защищённой HttpOnly cookie.

Перед публикацией выполните миграции production-базы:

```powershell
npx.cmd wrangler d1 migrations apply tandem-auth --remote --config wrangler.jsonc
```

Миграции добавляют парольную авторизацию, связи репетиторов с зарегистрированными учениками, редактируемые профили и серверную библиотеку видеоуроков. `0005_video_lessons.sql` создаёт видео и назначения ученикам; Worker проверяет владельца видео и действующую связь репетитор–ученик при каждом назначении и чтении. `0006_collaboration.sql` добавляет учебные группы, личные и групповые сообщения, а также метаданные файлов домашней работы. `0007_file_library.sql` добавляет переиспользуемое хранилище преподавателя, вложения сообщений и атомарные аренды демонстрации экрана. Миграция `0002_password_auth.sql` удаляет прежние аккаунты, сессии и данные кабинетов, как было запрошено. Миграции применяются отдельно от Worker deploy. После изменения схемы базы запустите указанную выше команду перед публикацией Worker.

Файлы домашних заданий хранятся отдельно от D1 в приватном Cloudflare Workers KV. Перед первым deploy создайте namespace и вставьте выданный идентификатор в `wrangler.jsonc`:

```powershell
npx.cmd wrangler kv namespace create HOMEWORK_FILES --config wrangler.jsonc
```

В D1 сохраняются только имя, MIME-тип, размер, папка, ключ объекта и список получателей. Максимальный размер одного файла — 10 МБ. Скачать файл могут назначенный ученик и преподаватель-владелец; удалить — только владелец. Один объект из `/api/files` можно повторно прикреплять к домашней работе, сообщению и доске без копирования данных в KV. Старый маршрут `/api/homework-files` сохранён для совместимости с уже созданными заданиями.

Репетитор связывает аккаунт через email подтверждённого ученического профиля. Связь хранится в D1 и видна обоим пользователям; расписание создаётся в часовом поясе репетитора и отображается ученику в его локальном часовом поясе. Время существующего занятия можно изменить без смены его идентификатора, привязанной доски и остальных данных. Минимальная длина нового пароля при сбросе — 8 символов.

В разделе «Сообщения» преподаватель общается с отдельными учениками, создаёт учебные группы и групповые чаты. Одно групповое домашнее задание разворачивается в отдельную копию для каждого участника, поэтому ответы и статусы учеников не пересекаются. На доске толщина инструмента выбирается компактным списком; перемещение полотна работает средней или правой кнопкой мыши, а точечный фон отключён.

Для отправки писем настройте в Cloudflare Worker:

- Secret `RESEND_API_KEY` — ключ Resend.
- Variable `AUTH_FROM_EMAIL` — `Tutdesk <noreply@tutdesk.space>` (задан в `wrangler.jsonc`).

Домен отправителя `tutdesk.space` обслуживается DNS-серверами Timeweb. Добавьте этот домен в Resend → Domains, затем перенесите предоставленные Resend записи проверки и отправки в редактор DNS Timeweb и дождитесь статуса Verified. Используйте точные значения из Resend; существующие почтовые записи Timeweb не удаляйте. Создайте API-ключ с правом Sending access для этого домена и сохраните в runtime secrets Worker как `RESEND_API_KEY`. Не помещайте ключ в Git или чат.

`AUTH_PUBLIC_ORIGIN` пока указывает на действующий адрес Worker. После подключения сайта к собственному домену отдельно обновите адрес ссылок подтверждения.

Без этих параметров регистрация не отправит письмо. Пример запроса Resend описан в [официальной документации](https://resend.com/docs/api-reference/emails/send-email).

Пароль хешируется PBKDF2-HMAC-SHA-256 с 100 000 итераций — пределом одного вызова в production Workers. Локальный workerd не воспроизводит этот предел, поэтому одной локальной проверки недостаточно. На Workers Free также действует лимит CPU; повышение тарифа увеличивает бюджет CPU, но не снимает предел PBKDF2. До подключения почтовых параметров регистрация возвращает `503 email_not_configured` до записи аккаунта. Отправка писем проверяется отдельно после настройки Resend.

Секреты LiveKit задаются отдельно: `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_URL`. Гостевой временный код `LIVEKIT_DEMO_ROOM_CODE` остаётся необязательным; его можно использовать для участников без аккаунта.

## Публикация через Cloudflare

Worker и D1 остаются API и базой данных Tutdesk. В настройках Cloudflare Builds задайте:

- Build command: `node build.mjs`
- Deploy command: `npx wrangler deploy`
- Root directory: `/`

Перед первым deploy с регистрацией примените D1-миграцию и добавьте параметры Resend. Worker будет собирать статические файлы из `dist/` и обслуживать API.

## Переезд сайта на Timeweb

Для переезда выберите VPS/VDS в **Timeweb Cloud**, а не обычный виртуальный хостинг: проекту нужен управляемый Nginx reverse proxy, чтобы браузер продолжал обращаться к аккаунтам и LiveKit через тот же домен. Стартовая конфигурация — **MSK 50: 2 vCPU, 4 ГБ RAM и 50 ГБ NVMe**. На официальной странице сейчас указан ориентир 1 080 ₽/мес при выбранном годовом периоде; перед заказом проверьте итоговую цену и период списания. Начните с почасовой тарификации и увеличьте ресурсы по фактической нагрузке.

Nginx будет раздавать содержимое `dist/` и проксировать `/api/*` на Cloudflare Worker; D1 остаётся в Cloudflare, как и выдача LiveKit-токенов. Поэтому API, аккаунты и данные кабинетов не нужно переносить на VPS. Обычный виртуальный хостинг Timeweb не подходит для такого proxy: на нём нельзя запускать постоянный Node.js сервис или системные службы.

Пример Nginx-конфига находится в `deployment/timeweb/nginx.conf.example`. Перед установкой замените `example.ru` на домен Tutdesk и настройте HTTPS. После появления домена задайте Cloudflare Worker-переменную `AUTH_PUBLIC_ORIGIN` равной `https://ваш-домен`: ссылки подтверждения почты и сброса пароля будут открывать сайт на Timeweb. Оставьте `ALLOWED_ORIGIN` равным адресу Worker, а в Nginx сохраните его в `Host` и `Origin` upstream-запроса.

## Остальные части проекта

- `frontend/` — ванильный JavaScript, HTML и CSS сайта.
- `cloudflare/` — Worker для аккаунтов, D1 и LiveKit.
- `backend/` — независимый Java/Spring Boot HTTP API; не участвует в сборке сайта.
- `build.mjs` — копирует сайт в `dist/`.

Java API и миграции PostgreSQL запускаются отдельно по инструкциям в [backend/README.md](backend/README.md) и [database/README.md](database/README.md).
