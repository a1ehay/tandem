# Tutdesk

Tutdesk — рабочее пространство репетитора и ученика: личные кабинеты, занятия, конференции LiveKit, интерактивная доска, задания и планер.

## Запуск и сборка

Для просмотра статического интерфейса откройте PowerShell в папке проекта:

```powershell
py -m http.server 8000 --directory frontend
```

Откройте <http://localhost:8000>. Чтобы собрать статические файлы:

```powershell
node .\build.mjs
```

Результат появится в `dist/`. Каталог `dist/` не добавляется в Git.

## Аккаунты и база данных

Пользователи и данные кабинетов хранятся в Cloudflare D1. Пароли хешируются на Worker с PBKDF2-HMAC-SHA-256. После регистрации Tutdesk отправляет одноразовую ссылку подтверждения email; сессия хранится в защищённой HttpOnly cookie.

Перед публикацией выполните миграции production-базы:

```powershell
npx.cmd wrangler d1 migrations apply tandem-auth --remote --config wrangler.jsonc
```

Миграция `0002_password_auth.sql` удаляет все существовавшие аккаунты, сессии и данные кабинетов, как было запрошено, затем добавляет поля паролей и таблицу подтверждений. Она применяется отдельно от Worker deploy.

Для отправки писем настройте в Cloudflare Worker:

- Secret `RESEND_API_KEY` — ключ Resend.
- Variable `AUTH_FROM_EMAIL` — адрес отправителя на подтверждённом в Resend домене, например `Tutdesk <noreply@ваш-домен>`.

Без этих параметров регистрация не отправит письмо. Пример запроса Resend описан в [официальной документации](https://resend.com/docs/api-reference/emails/send-email).

Пароль хешируется PBKDF2 в Worker. На Workers Free лимит вычислений составляет 10 мс на запрос; проверьте метрики CPU после включения регистрации. Если Worker упирается в этот предел, потребуется Workers Paid, где лимит вычислений выше.

Секреты LiveKit задаются отдельно: `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_URL`. Гостевой временный код `LIVEKIT_DEMO_ROOM_CODE` остаётся необязательным; его можно использовать для участников без аккаунта.

## Публикация через Cloudflare

Worker и D1 остаются API и базой данных Tutdesk. В настройках Cloudflare Builds задайте:

- Build command: `node build.mjs`
- Deploy command: `npx wrangler deploy`
- Root directory: `/`

Перед первым deploy с регистрацией примените D1-миграцию и добавьте параметры Resend. Worker будет собирать статические файлы из `dist/` и обслуживать API.

## Переезд сайта на Timeweb

Для переезда выберите VPS/VDS в **Timeweb Cloud**, а не обычный виртуальный хостинг: проекту нужен управляемый Nginx reverse proxy, чтобы браузер продолжал обращаться к аккаунтам и LiveKit через тот же домен. Стартовая конфигурация — **MSK 50: 2 vCPU, 4 ГБ RAM и 50 ГБ NVMe**. На официальной странице сейчас указан ориентир 1 080 ₽/мес при выбранном годовом периоде; перед заказом проверьте итоговую цену и период списания. Начните с почасовой тарификации и увеличьте ресурсы по фактической нагрузке.

Nginx будет раздавать содержимое `dist/` и проксировать `/api/*` на Cloudflare Worker; D1 остаётся в Cloudflare, как и выдача LiveKit-токенов. Поэтому API, аккаунты и данные кабинетов не нужно переносить на VPS. Обычный виртуальный хостинг Timeweb не подходит для такого proxy: на нём нельзя запускать постоянный Node.js сервис или системные службы.

Пример Nginx-конфига находится в `deployment/timeweb/nginx.conf.example`. Перед установкой замените `example.ru` на домен Tutdesk и настройте HTTPS. После появления домена задайте Cloudflare Worker-переменную `AUTH_PUBLIC_ORIGIN` равной `https://ваш-домен`: ссылки подтверждения почты и сброса пароля будут открывать сайт на Timeweb. Оставьте `ALLOWED_ORIGIN` равным адресу Worker, а в Nginx сохраните его в `Host` и `Origin` upstream-запроса.

## Остальные части проекта

- `frontend/` — ванильный JavaScript, HTML и CSS сайта.
- `cloudflare/` — Worker для аккаунтов, D1 и LiveKit.
- `backend/` — независимый Go HTTP-сервис; пока предоставляет `/healthz` и не участвует в сборке сайта.
- `build.mjs` — копирует сайт в `dist/`.

Go-сервис запускается отдельно из `backend/` командой `go run ./cmd/tandem-api`.
